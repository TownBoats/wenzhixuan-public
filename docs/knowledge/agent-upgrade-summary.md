整理日期：2026-11-01。范围是本次 Agent 升级及后续同一轮产品迭代，不仅是 G 阶段。代码基准为 `347a6a44f44356102b3e7cd7d6ef393f4c784b2e`；过程证据见 [历史归档](../archive/agent-upgrade-2026-11-01/README.md)。

## 1. 交付目标与结果

本次把“页面解析模型标签并驱动问答”的旧实现，迁移为“模型调用具名工具、程序执行并返回工具结果、会话状态机驱动教学交互”的结构。产品仍是纯前端的苏格拉底式学习应用：主模型讲解与提问，副模型提供分档候选答案，学生选择、手答或跳过，一轮问题全部处理后自动继续。

A–F 完成基线探针、运行层、会话层、页面、历史与取消重试；G 补充配置入口、移除运行时开关并改善阅读与作答界面。后续提交增加可交互 HTML、SVG 讲解卡、工具参数流式预览、结构化候选答案及触屏作答/等待设置。

A–F 的验收见原阶段记录；G-2、G-1 分别由用户于 2026-11-01 明确人工验收。后续探索提交的现行能力可由源码确认，不能把 A–F 的历史验收自动外推为所有新增能力均已完成当前 HEAD 的真实端点验证。

## 4. 关键设计取舍

- 先验证真实端点的工具闭环，再投资完整架构；不以 SDK 类型存在推断服务端支持。
- 提问工具先完成调用与结果配对，再停止等待学生；工具执行不悬挂等待人类。
- 模型输出、展示 parts、存储数据采用不同投影；reasoning 不进入后续模型上下文，也不落入历史。
- 从“单问题硬限制”转为多问题软引导，保留每个调用与结果，副模型并发上限控制成本。
- 新数据写 v2、旧数据现场投影，不自动批量迁移；删除和重命名等用户操作另有跨键语义。
- 副模型先复用思路、再独立适配，最终改为工具通道结构化输出，以适应真实端点兼容性。
- 投递时保留开关，稳定后 G-1 移除开关；保留旧文件不再等于保留界面回退入口。

决策如何被替代以及不能外推的结论见 [开发复盘](../harness/RETROSPECTIVE.md) 和 [现行业务知识](agent-upgrade.md)。
