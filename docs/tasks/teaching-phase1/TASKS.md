# 教学引擎一期：任务与判据

源码基准：`a18d017`。“现状”已对照源码；“做法”是方案，未实施。范围与决定见 [任务契约](README.md)。

## T1 公式渲染

**状态（2026-11-25）：已实现，用户已验收（“ok，修好了”）。** 基准 `156b95b` + 工作区；Windows / Node v22.22.1 / Chrome headless。单元测试 236/236（新增 7），`vite build` 与改动文件 eslint 通过；浏览器用临时页渲染实际组件，桌面 900px 与 390px iframe，长公式在自身范围滚动、页面不横溢。未用真实模型，未在实体手机或完整答题流程中验证。答题卡的 CDN 样式一并换成本地样式。

**现状：** `MarkdownContent.jsx` 只启用 `remark-gfm`，供教学正文和问题磁贴使用；`MarkdownRenderer` 已启用 `remark-math` 与 `rehype-katex`，供答题卡使用。教学指令要求模型用 `$` 写公式。

**做法：**
- `MarkdownContent` 接入两个现有插件；公式错误不得使整段渲染失败。
- 不沿用每次渲染插入的 CDN `<link>`：它固定为 0.16.0，锁文件中的 katex 是 0.16.45。改为打包本地 CSS，并把 `katex` 按锁定版本列为直接依赖。
- 处理货币误判，例如在渲染前转义内容含中文的疑似货币片段；不得影响代码块和合法公式。
- 不启用 `rehype-raw`，HTML 仍按文本显示。

**判据：** `$2\log_2(n+1)$` 和 `$$` 块公式在正文与磁贴显示正确；`苹果 $5，梨 $10` 保持原文；代码块内的 `$` 不变；流式未闭合公式不报错；窄屏长公式可横向滚动且不撑破页面。

**影响与回退：** 仅展示层及一个直接依赖，不动数据。

## T2 选项模型上下文

**现状：** `generateAnswerOptions` 只收到问题和主模型可选填写的 `context`（上限 2000 字）。程序不附带历史，提示词却要求“结合前面的讲解”。主模型不填 `context` 时，副模型只看到问题。

**做法：**
- 在 `src/agent/` 新增纯函数，从本轮发给主模型的 `messages`、本轮已生成正文和主模型 `context` 组装候选上下文。
- 优先级：问题 > 主模型 `context` > 本轮正文 > 被引用内容（T5 后）> 最近几轮讲解与作答。超预算时从最低优先级开始截断；初始预算 6000 字，T6 用样本校准。
- 不放 SVG/HTML 源码、reasoning、工具元数据和候选项；图只放标题。
- 本轮正文由运行层从 `text-delta` 累积。**先用 mock 证明**工具执行时已能取得提问前的正文；若时序不稳定，以主模型 `context` 为准。
- 教学指令要求 `context` 写清回答所需的事实和前文结论；T5 后，问题依赖较早内容时须带引用。
- 副模型默认提示词补充：材料不足时不编造讲解中没有的事实。不覆盖用户自定义提示词；已缓存的默认提示词如何更新，实施时核对 `prompts.js` 后定。

**判据：** 最近几轮窗口内的依赖结论和主模型 `context` 会进入副模型请求；T5 后，窗口外的被引用结论也会进入；超预算时高优先级内容保留；请求体不含源码与 reasoning；副模型失败、超时、取消的行为不变。

**影响与回退：** 副模型 token 用量上升；不动存储。

## T3 卡住时直接引导

**现状：** 题目只有作答和跳过；跳过序列化为“学生选择了跳过，未作答”。两份教学指令都禁止直接给结论。全部题目处理完才起新一轮。

**做法：** 按 [ADR-004](../../decisions/ADR-004-direct-guidance.md)。
- 问题磁贴和答题卡增加“直接讲给我”。
- 数据上仍是 `skipped`，另加可选字段 `resolution: 'explain'`。
- 点击后立即起新一轮；同轮其余待答题在同一次转换中标为 `skipped` + `resolution: 'deferred'`，只显示“已暂缓”，不可再作答。已答的题照常进入汇总。
- 暂缓题序列化为：`针对问题「…」：（学生暂未作答，先处理其他请求；之后可按需重新提问）`。
- 固定序列化文案：`针对问题「…」：（学生想不出来，希望直接讲解这一点，未作答）`。
- `socratic.md` 增加递进讲解规则：从学生已会的一步出发，一次只讲一个点，展示它如何推到下一步，再用一个小问题确认。示例：1+1=2 → 1×3=1+1+1。收到该请求时，允许直接给出这一点的结论。

**判据：** 单题、多题点击后都立刻起新一轮；已答题进汇总、其余题显示已暂缓；暂缓题不被说成主动跳过；双击只生效一次；序列化文案精确；`resolution` 可保存、恢复、备份往返，未知值清洗为空；普通跳过文案不变；TXT 导出能区分跳过、请求讲解与暂缓；键盘可操作，中英文案齐全。

**影响与回退：** 旧代码丢弃未知字段，显示为普通跳过；已发送的回答文本不受影响。

## T4 学习 plan、前置概念与概念抽取

**现状：** 三个工具，主运行 `MAX_STEPS = 3`、120 秒；教学指令有摸底要求，没有结构化记录。

**先做探针：** 在目标端点上用新工具跑“plan + 图 + 提问”，记录步数、耗时、是否并行调用、拒绝率。不通过则调整方案后再实施。

**做法：** 按 [ADR-003](../../decisions/ADR-003-teaching-state.md)。
- 新工具 `update_learning_plan`，仅 `socratic` 注册，不停止运行。
- 输入目标、概念清单、前置关系、当前概念和下一步；每次传增量，程序合并并返回最新全量快照。
- 概念状态：`unknown` / `gap`（缺口）/ `claimed`（自评会）/ `verified`（已验证）。
- `verified` 必须附学生原话。程序只接受手答或自由输入中的连续原文，不接受点选的候选答案；校验失败时降为 `claimed` 并在结果中告知模型。
- 教学指令：新主题先建 plan；先确认前置概念；发现缺口先更新 plan 再补；学生改目标时更新 plan；一轮最多更新一次。
- `MAX_STEPS` 提议 3 → 5，总时限不变，以探针为准。
- 界面：页头下方常驻一行，显示目标、当前概念和进度；点击展开浮层，列出概念、前置、状态与调整入口。没有 plan 时不显示；工具卡不显示 plan 原始数据。
- 调整：浮层内输入要求并提交，立即起新一轮。现状是有待答题时不能发消息，因此新增专用命令，其余待答题按 T3 的规则暂缓；运行中禁用，空输入不生效。提交的文字保存为 `input` 来源，学生原话可用于证据校验。
- `contextSchemas` 登记新工具，使上下文占用估算包含它。

**判据：** 真实端点上新主题首轮产生合法 plan；增量合并保留未提及概念；重复 ID、循环前置、未知字段被拒绝并给出原因；伪造原话不能变为 `verified`；重试、取消、失败轮不污染 plan；刷新与备份导入后一致；旧会话无 plan 时正常续聊；有待答题时提交调整会立即续轮且原题暂缓；常驻行在 390px 不换行溢出，键盘可展开和关闭；TXT 导出不含 plan 原始数据；达到步数上限时沿用 `limit_reached` 结果。

**影响与回退：** 旧代码把该工具显示为通用工具卡。旧代码续聊时，历史里会有未注册工具的配对调用，端点能否接受需在 T6 验证。

## T5 引用与跳转

**现状：** 图的工具结果含标题与源码，没有为引用设计的稳定编号；`MarkdownContent` 的链接统一新窗口打开。

**做法：**
- `explain_card` 与 `visualize` 的就绪结果增加程序生成的短 `refId`，例如 `fig-k3x9ab`，会话内不复用；显示用的“图 N”由投影按顺序计算。
- 模型在正文用 `[图](#ref:fig-k3x9ab)` 引用，界面渲染为页内跳转。探测确认该链接不会被现有 URL 清洗移除。
- `ask_question` 增加可选 `refs`（最多 3 个）。未知引用忽略，不拒绝问题，并在结果中告知模型。
- 问题磁贴和答题卡显示引用入口；跳转后高亮并移动焦点，提供“回到原处”。
- 讲解文字通过 plan 概念定位：`#concept:<id>` 跳到该概念最近一次成为当前概念的轮次。
- T2 的“被引用内容”：图取标题与所在轮正文，概念取对应轮正文。

**判据：** 有效引用可跳转并返回；失效引用显示为普通文字；`refs` 可往返保存；旧图无 `refId` 仍正常显示；伪造链接只能产生页内定位，不能执行脚本；重试轮的旧图不与新图混淆；窄屏可用。

**影响与回退：** 旧代码忽略 `refs`，正文引用退化为无效链接。答题时并排看图属二期。

## T6 集成验证与评估

- 自动：全量单元测试、`session-loop`、改动文件 eslint、构建。
- 浏览器：桌面与 390px；公式、直接讲解、plan 常驻行与调整、引用跳转、旧会话续聊、备份往返。
- 承接历史未验项：三工具、副模型在目标端点的实际表现（原 V-02/V-03），上下文占用与接口 usage 的对照（原 V-04）。
- 真实模型：至少 5 个主题，覆盖数学、编程、概念类，每个至少 6 轮；记录端点与模型，不记录凭据。

| 指标 | 看什么 |
| --- | --- |
| plan 遵循 | 讲解是否偏离当前概念；偏离时是否先更新 plan |
| 概念质量 | 是否准确、过碎、重复 |
| 前置判断 | 是否漏掉学生明确暴露的缺口 |
| `verified` 误报 | 有无附了原话却并未理解的情况 |
| 候选答案 | 是否与讲解矛盾、是否编造 |
| 直接讲解 | 是否只讲一个点、有递进、有后续确认 |

结果由用户判定是否接受，再决定二期。未跑的项目如实写“未验证”。
