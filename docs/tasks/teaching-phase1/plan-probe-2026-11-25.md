# T4 plan 探针结果

日期：2026-11-25。基准：`bafe267` + 工作区的 `scripts/probe-plan-tool.mjs`。环境：Windows / Node v22.22.1。
端点与模型：DeepSeek 官方端点、`deepseek-flash`；用户提供测试 key，未写入仓库。
动作：`node scripts/probe-plan-tool.mjs`，两个主题各 4 轮，退出码 0。副模型未参与，提问直接返回就绪。

| 指标 | 结果 |
| --- | --- |
| 轮次完成 / 以提问结束 | 8/8 / 8/8 |
| 首轮先建 plan 再提问 | 2/2 |
| 最大步数 | 2（现行上限 3，放宽到 8 观察） |
| 最长单轮耗时 | 37.6 秒（不含生成候选答案） |
| 并行调用 | 8/8 轮 |
| plan 被拒 | 0/7 次 |
| 提问漏写 `context` | 0/16 |
| 每轮最多更新一次 | 8/8 |

人工看原始记录：

- 一个概念变为 `verified`，引用的是学生完整原话，理由也正确。
- 学生说“我觉得我全懂了”后，没有标 `verified`，改为继续检验。
- 学生改目标后，goal、概念和约定都随之更新。
- 约定跨轮保留，最初的约定都在。

问题：

- **约定混入其他内容：** 目标、推导结论也被写进 `conventions`。
- **漏更新：** bayes 第 3 轮学生答对了读法，没有更新 plan。
- **缺口判断偏宽：** bayes 第 2 轮把没有暴露问题的“患病率”也标为 gap；脚本对两题用同一句回答，可能是诱因。
- **题干不自足：** 出现“对这个数组”，未写出数组。
- **无正文：** 两轮没有讲解正文，其中 bayes 第 2 轮只有图和提问。
- plan 与提问常在同一步并行，提问后本轮即停，模型到下一轮才看到拒绝或降级的通知。

限制：只有一个模型、8 轮脚本化对话；没有出现伪造证据或 plan 被拒，真实拒绝路径未覆盖（仅 mock 覆盖）。不代表教学效果。

## 对 T4 的影响

- 采用 ADR-003 的四工具方案。
- `MAX_STEPS` **保持 3**，不改为 5；总时限不变。
- `conventions` 的说明限定为符号、编号、例子参数，明确不含目标、结论和规则推导。
- 教学指令补充：学生答对或暴露缺口的当轮须更新；没有证据不标 gap；先讲解再提问，不能只出图。
- “懂了 / 会了 / 我知道了”这类纯自评，即使是原话也不能作为 `verified` 的证据，由程序拦截。
