# ADR-003：教学状态作为工具结果的投影

日期：2026-11-25。状态：**提议**，待用户审阅。源码基准：`a18d017`。
依据：用户选定一期“快速修复 + 教学打底”，并说明学习链路撤销原因为提取质量和展示形式不好。

## 问题

学习 plan、前置判断、概念抽取、引用跳转需要同一份结构化状态，并且要回流教学。此前的学习链路是事后旁路提取、不回流教学，已撤销，见 [业务知识](../knowledge/agent-upgrade.md)。

## 选项

| 选项 | 优点 | 代价 |
| --- | --- | --- |
| A 主模型工具 `update_learning_plan`，由已保存的工具结果折叠出状态 | 教学前先定概念；无独立模型请求；不加存储键；重试与取消沿用现有规则 | 占步数；质量依赖主模型 |
| B 每轮由副模型旁路提取 | 不占主运行步数 | 与学习链路同路，未解决质量问题；有延迟，要同步两份状态 |
| C 教学前单独调用一次规划模型 | 规划专注 | 多一次等待；更新仍需 A 或 B |

## 结论

采用 A。针对撤销的两个原因：

- **质量：** 概念由主模型在教学前定义并持续使用，不事后归纳；升为“已验证”须有学生原话，由程序校验。
- **展示：** 不放消息流末尾；一期用页头抽屉，二期并入新布局。

学习链路的 ADR-001 曾放弃主模型工具，理由包括占步数、与教学争注意力、自评偏差。本次取舍不同：状态要先于教学存在并指导教学，旁路做不到。步数由探针和 `MAX_STEPS` 调整处理，自评偏差由 `claimed` / `verified` 区分和原话校验缓解。

## 状态与接口

```text
plan     { goal, currentConceptId, nextStep, concepts[] }
concept  { id, name, status, requires[], evidence }
status   unknown | gap | claimed | verified
```

- 概念 `id` 由模型首次给出、程序校验唯一，之后按 `id` 更新；上限 20 个，名称 2–20 字。
- `requires` 只能引用已有或同次新增的 ID，拒绝循环。
- `evidence` 是字符串。结构保持扁平，不触及存储清洗的深度上限 6。
- 工具每次返回最新全量快照；不改 `buildSystemPrompt` 的单参数约束。
- 先前状态与学生原话由会话层以快照传入运行层，工具不读存储。
- 从状态合格轮次的 `modelMessages` 折叠，与模型上下文同口径；失败、取消、中断轮不计入。
- 图的 `refId` 由程序生成，随工具结果保存；“图 N”只是显示编号。

## 兼容与回退

- 不新增存储键、不升 `schemaVersion`、不改备份格式。
- 旧会话没有 plan：续聊时由模型按需新建，不回溯提取。
- 旧代码读新会话：plan 显示为通用工具卡，问题的 `refs` 被丢弃，其余内容保留。旧代码续聊对端点的影响需验证。

## 放弃的代价与遗留风险

- 弱模型可能不建 plan 或建得差；程序只能保证结构，不能保证教学质量。
- 只点选候选答案的学生，概念最多到 `claimed`，需要手答才能验证。
- 长会话中的旧快照仍占上下文，由后续压缩处理。
- 若探针显示目标端点不能稳定使用第四个工具，改用 C 并另写替代 ADR。
