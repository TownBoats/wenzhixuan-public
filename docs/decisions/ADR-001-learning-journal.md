# ADR-001 学习记录（Learning Journal）作为第四种数据投影

- 日期：2026-11-01
- 状态：**已接受**（2026-11-01 用户审阅后授权实施；实施中的三处修订见 §3.7）
- 决策人及授权依据：用户在 2026-11-01 会话中确认——①第一版只做复盘路线图，学习记录只读旁路，不回流教学上下文；②事件六类够用；③学习目标由提取器自动推断；④只考虑单一会话。
- 源码基准：`347a6a44f44356102b3e7cd7d6ef393f4c784b2e`（dev），本 ADR 未改源码。

## 1. 问题与约束

学习结束后缺少能把概念串联起来的复盘：学生起点卡在哪里、有过哪些误区、怎样被化解、最后还剩什么。需要一份**按时间演进的学习路线图**，而不是概念掌握度快照。

约束：

- 产品是纯前端，模型请求直达端点，数据在浏览器本地存储（见 [业务知识 §1](../knowledge/agent-upgrade.md)）。
- `src/agent/` 不导入 React、不访问存储；会话生命周期归 `useChatSession`/reducer。
- 主运行预算 `MAX_STEPS = 3`、120 秒；教学提示词已较重。
- 不改变 `chat_histories_v2` 存储格式，不改变发给主模型的上下文投影。
- 候选档位是学生自评，不等于掌握（业务知识 §1）。

## 2. 考虑的选项

| 选项 | 内容 | 结论 |
| --- | --- | --- |
| A 主模型工具顺手记录 | socratic 新增 `record_understanding` 工具 | 放弃：占步数与关键路径，评估与教学争注意力，自评偏差，结果不可重算 |
| B 结束时一次性读全文生成 | 用户打开复盘时副模型读整段会话 | 放弃作为主路径：成本随长度线性增长，长文中段卡点易丢失 |
| **C 增量提取 + 确定性路线图 + 按需叙事** | 每个“已闭合教学单元”由独立提取器产出结构化事件；路线图由纯函数从事件投影；串联讲解按需由模型基于事件生成 | **采纳** |

第一性原理说明：主模型提取的**额外输入 token 接近零**（历史本来就要发），独立提取器反而要重读增量。选择 C 的理由是关注点分离、离开关键路径、可重算与可评估，不是“省 token”。真正的 token 节省（用学习状态替代早期历史）属于后续阶段，见 §6。

## 3. 结论

### 3.1 教学单元（提取粒度）

- turn T 在其后一轮 T+1 已创建时视为**闭合单元** `U(T)`：输入为 T 的用户输入（仅首单元用于推断目标）、T 最新 runId 的正文片段、可视化/讲解卡**仅标题**、T 的问题（题干、学生所选档位与文本、手答、跳过），以及 T+1 用户输入中 `source === 'input'` 的自由文本。
- 仅 `completed` / `awaiting_user` 的 T 参与，与模型上下文口径一致；failed/cancelled/interrupted 跳过。
- 会话最后一轮没有后继时为**尾单元**，只在打开路线图时按需提取；之后若会话继续，尾单元按新键重提取并替换。
- 幂等键：`unitKey = ${T.id}:${T.runId}:${T+1.id ?? 'tail'}`。同键结果**整单元替换**，不追加。

### 3.2 事件与状态

事件类型六选一：`stuck`（卡点）、`misconception`（误区）、`breakthrough`（突破）、`verified`（检验通过）、`residual`（残留问题）、`goal_change`（目标变化）。首单元额外产出 `goal`。

节点结构：`topic`（概念主题，2–10 字名词短语，如「派生与继承」，是节点标题）、`type`（上面六类之一，界面降为小标签）、`points`（1–2 条短 bullet）、`evidence`。**标题写概念，不写状态**——「不理解派生」不是主题。同一概念在整条链路复用同一说法。

**证据守卫**：`stuck / misconception / breakthrough / verified` 必须带学生原话 `evidence.quote`，程序校验其（规范化后）为本单元学生文本的子串，否则丢弃该事件——无证据不下结论。

学习状态 = 按单元顺序折叠事件；提取第 k 单元时只传入前 k−1 单元折叠出的**紧凑状态**（目标、概念表、未化解误区），输入规模不随会话增长。

### 3.3 存储

- 独立键 `learning_journals_v1`（数组，按 `conversationId`），`schemaVersion: 1`；不改 `chat_histories_v2`。
- 学习记录是**可由会话历史重新推导的派生数据**：与会话两次写入不要求原子性，丢失可补跑。
- 删除会话时同步删除对应学习记录；存储失败显式返回原因（沿用 `historyStore` 的返回值风格）。
- 不存凭据、reasoning、工具 HTML/SVG 载荷。

### 3.4 调用与调度

- 提取器为 `src/agent/services/extractLearning.js`：单次非流式 `generateText` + 强制工具 `submit_learning_update`（与候选答案服务同一结构化通道、同一 DeepSeek/智谱关闭思考的兼容处理）；模型可注入以便 `MockLanguageModelV3` 测试。
- 第一版复用副模型配置；未配置时功能显示为不可用，不影响教学。
- 调度为**对账式**：由纯函数计算“已闭合但未提取的单元”，每会话串行处理；失败标记该单元可重试，且**遇错即停**（修订见 §3.7）：后续单元依赖前序折叠状态，跳过失败单元会让链路静默缺一段。
- 自动提取只针对已存在学习记录的会话的新单元；无记录且积压单元较多的旧会话，由用户在面板中显式点击生成，避免意外批量消耗。

### 3.5 路线图与叙事

- 路线图结构（目标、起点卡点、概念顺序与前置关系、每节点事件时间线、未化解问题）由纯函数确定性投影，不调用模型。
- “串联讲解”文字按需由模型基于路线图投影生成，按事件摘要哈希缓存，事件变化后提示可重新生成。

### 3.6 不变量

- 第一版学习记录**不进入主模型上下文**，不改 `buildModelContext`。
- 提取器失败、超时、取消均不改变 turn 状态，不弹教学错误。
- 迟到的提取结果若其 `unitKey` 已不在当前会话的单元集合中（会话切换、重试换 runId），直接丢弃。

### 3.7 实施修订（2026-11-01）

评审发现的三处缺口，实施时按以下口径落地：

1. **结果有效性用指纹，不只靠 `unitKey`**。单元额外存 `inputHash`（该单元提取输入 + 前序状态摘要的哈希）、`prevDigest`（前序折叠状态）、`extractorVersion`。任一变化即判为过期。这覆盖了「尾轮部分作答时键不变、输入变了」与「前序重算后后续结果失效」两种情形。
2. **失败即停，不跳过**。`nextPendingUnit` 返回第一个待提取单元，失败单元会一直占据队首直到重试成功；因此后续结果不会建立在缺失状态上，也不需要级联失效。
3. **`verified` 从严**。只有学生在预测或解释类问题上给出正确理由才记；选对选项、「懂了」、教师讲得好都不算。证据必须取自手答或自由输入，点选候选的文本是副模型生成的，不能当原话。
4. **节点以概念为主题**（2026-11-01 用户反馈后修订）。原设计把 `stuck` / `residual` 这类状态当作节点标题，展开后满屏「卡点」「未解」，读者看不到在学什么。现在 `topic` 是标题，`type` 退为小标签；折叠也改为「同主题同状态」才合并，同主题的卡点到转折保留为两个节点，演进不被压平。`extractorVersion` 记为 `v2`，v1 结果没有 `topic`，会自动失效重算（每个单元一次调用）。

同一轮里三条的实现口径也固定下来：证据校验失败只丢单个节点；全丢视为成功但 0 节点（避免无限重试）；保存失败显式报出，不假装已存。

## 4. 放弃选项及代价

- 放弃 A：主模型的即时判断（含其教学意图）不直接可得，需提取器从正文推断。
- 放弃 B 作为主路径：多一套增量调度与幂等逻辑；B 的能力以“尾单元 + 显式补全”方式部分保留。
- 每个闭合单元多一次副模型调用（估算输入 3–6k token），成本由用户的副模型配置承担。

## 6. 遗留风险及后续条件

- **提取质量**是主要不确定性：先建立 5–10 段真实会话的人工标注样本，用于对比提示词版本；mock 测试不代表真实模型能力。
- 只点选项、无手答的单元证据弱，可能产出很少事件；这是证据守卫的预期代价。
- 多标签页同时写同一键无协调，沿用现有历史存储的已知限制。
- 回流教学（摘要注入）、历史压缩、跨会话学习档案均为后续独立决策，需新 ADR。
