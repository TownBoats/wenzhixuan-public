# ADR-002：完整文件备份与跨设备导入

日期：2026-11-14。状态：已实施，待用户验收。源码基准：`db6fd18` 上的本轮工作区。

## 目标与范围

用户要求导出完整数据并跨设备同步。当前产品是纯前端，无账户或云存储；本轮交付设置中的文件导出、导入预览及合并恢复，不新增远端服务或自动同步。

验收判据：新旧会话、回答/待答问题、图示、模型配置、提示词、偏好在新存储中恢复；重复导入不重复会话；坏文件不写入；写入失败明确回退结果；导入后当前会话和配置立即更新，无模型请求。

## 格式与兼容

- 新文件为 UTF-8 JSON：`format: "wenzhixuan-backup"`、`version: 1`、`exportedAt`、`includesCredentials`、`data`。
- `data` 是显式白名单存储键到原始字符串的映射；不枚举/复制同 origin 的无关键，不导出运行控制器、内存 reasoning 或未发送草稿。
- 包含 `chat_histories_v2`、`chat_histories`、模型配置/提示词、答题偏好/尺寸、开发者开关及提示关闭状态；兼容保留已退役的 `learning_journals_v1`，不恢复学习链路功能。
- 原始字符串允许损坏数据被备份抢救；格式损坏的备份内容无法直接导入，不以“跳过损坏记录”伪装完整恢复。
- 导入支持此格式及旧版直接导出的 v1 会话数组，支持 BOM；未知版本、未知键、重复 ID、坏配置/记录拒绝，文件上限 50 MB。
- v2 导入经过既有 `sanitizeConversation` 存储投影，不把 reasoning、预览或 U+200B 写回历史；v1 原始结构保留，仍由现有适配器展示。
- 日常历史键与 schemaVersion 不变，无批量迁移、无旧数据清除。备份版本号与会话 schemaVersion 独立。

## 合并与恢复

各历史集合按自身 ID 合并；时间戳较新者胜出，相同时间保留本机；不存在的记录新增，本机独有记录保留。v1/v2 两键分别合并，展示继续遵循 v2 优先。预览计数是两键的记录条数，可能包含同 ID 的新旧副本。

旧学习记录按 conversationId/updatedAt 合并，仅为兼容备份；不执行提取。文件中设置覆盖本机对应键，缺省键保留；不传播删除，不合并同一会话的分叉轮次。因此这是文件迁移/手动同步，不是双向持续同步；双方都编辑过同一会话时应先分别备份。

导出/应用导入前由历史 hook 检查本轮已结束，并确认当前会话已保存；保存失败重试，失败不假装导出成功。保存签名只在成功后推进，保留用户重命名标题。打开的旧会话无变化时不强制生成 v2 副本。

预览不写存储。确认时重新读取本机数据并生成计划；写入失败按逆序恢复已写键，恢复失败单独提示 `rollback_failed`。localStorage 多键写入不具备事务，崩溃、多标签页并发不在保证范围内。

成功后通过会话命令重新打开当前 ID（不存在则打开最近记录），刷新历史列表和配置快照；模型表单及答题偏好重建以显示导入值，草稿保留，不刷新页面、不自动重发请求。

## 凭据取舍

完整迁移默认包含接口地址和 API Key，下载前始终显示明文 JSON 提示；用户可取消勾选，去除模型配置的连接地址/密钥，仅保留模型名及思考/上下文参数。去掉连接地址是因为 URL 本身可能携带凭据。

不含凭据的备份导入时合并模型参数，保留目标设备的密钥和地址。此选项不是任意对话/提示词/工具载荷的通用秘密检测器；界面明确说明私人内容仍可能存在。文件不加密、不上传，用户自行保管；不在公共仓库存入真实备份或配置。

## 替代关系与限制

取代 ConfigPanel 中“不提供历史导入导出”的旧边界说明。旧 SettingsPanel 的 v1 专用管理代码保留，但不是当前入口；新旧用户数据兼容不随旧 UI 是否存在而改变。真实模型、实体手机、浏览器配额差异和线上发布需要分别验收。
