# ADR-004：直接引导与教学方式

日期：2026-11-25。状态：一期“立即开始”已由用户确认，暂缓规则随方案采用，“直接讲给我”已实施并由用户验收；plan 调整随 T4 实施并验收；二期部分未实施。源码基准：`a18d017`。
依据：用户选择“随时切换 + 卡上按钮”；所选一期范围只含卡住时直接引导。

## 一期：“直接讲给我”

| 选项 | 说明 | 结论 |
| --- | --- | --- |
| 新增问题状态 `explain_requested` | 语义清楚 | 放弃：旧代码会把未知状态清洗为 `pending`，回退后旧题重新显示为待答 |
| 复用 `skipped` + 可选 `resolution: 'explain'` | 旧代码丢弃字段后仍是跳过 | **采纳** |
| 直接发一条普通用户消息 | 不改数据 | 放弃：有待答题时不能发送，且会丢失与题目的对应关系 |

学生请求作为下一轮 user 消息进入上下文，不是补写的工具结果。

用户确认 **立即开始**。多题时其余待答题的处理：

| 选项 | 结论 |
| --- | --- |
| 保持待答 | 放弃：新一轮已开始，旧题只能在末轮作答，会变成无法处理的待答 |
| 记为普通跳过 | 放弃：学生没有主动跳过，会误导模型判断 |
| `skipped` + `resolution:'deferred'` | **采纳**：只显示“已暂缓”；模型得知未作答，之后可按需重新提问 |

已答的题照常进入汇总。整个处理是一次 reducer 转换，双击只生效一次。这改变了“全部处理完才续轮”的旧规则，仅限直接讲解与 plan 调整两个入口；正常作答和跳过不变。

plan 调整沿用同一规则：有待答题时普通消息仍不能发送，学生从 plan 浮层提交调整要求，其余题暂缓并立即续轮。

## 二期方向：直接教学开关

以下仅记录约束，二期开工时再定稿：

- 现有规则是有待答题时拒绝切换模式，与“随时切换”冲突。提议改为运行中不可切换，待答时可切换、**从下一轮生效**；各轮记录自己的教学方式快照。
- 不宜把 `direct` 写成持久化的新模式 ID：旧代码没有该模式对象，回退后无法续聊。提议另设可选的教学方式字段，缺失即“追问”，旧代码会丢弃它。
- 重试须沿用原轮教学方式。现状是重试运行取当前会话模式，不取该轮 `modeSnapshot`，需一并处理。
- 直接教学仍可用图、plan 和提问组件，但减少提问。

## 遗留风险

学生可能过度使用按钮，少了思考。一期不限次数，T6 观察后再定是否加提示。
