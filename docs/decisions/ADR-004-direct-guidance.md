# ADR-004：直接引导与教学方式

日期：2026-11-25。状态：**提议**，待用户审阅。源码基准：`a18d017`。
依据：用户选择“随时切换 + 卡上按钮”；所选一期范围只含卡住时直接引导。

## 一期：“直接讲给我”

| 选项 | 说明 | 结论 |
| --- | --- | --- |
| 新增问题状态 `explain_requested` | 语义清楚 | 放弃：旧代码会把未知状态清洗为 `pending`，回退后旧题重新显示为待答 |
| 复用 `skipped` + 可选 `resolution: 'explain'` | 旧代码丢弃字段后仍是跳过 | **采纳** |
| 直接发一条普通用户消息 | 不改数据 | 放弃：有待答题时不能发送，且会丢失与题目的对应关系 |

学生请求作为下一轮 user 消息进入上下文，不是补写的工具结果。多题时仍等全部处理完再起新一轮；若用户要求立即开始，需另定其余题的处理，并修改本 ADR。

## 二期方向：直接教学开关

以下仅记录约束，二期开工时再定稿：

- 现有规则是有待答题时拒绝切换模式，与“随时切换”冲突。提议改为运行中不可切换，待答时可切换、**从下一轮生效**；各轮记录自己的教学方式快照。
- 不宜把 `direct` 写成持久化的新模式 ID：旧代码没有该模式对象，回退后无法续聊。提议另设可选的教学方式字段，缺失即“追问”，旧代码会丢弃它。
- 重试须沿用原轮教学方式。现状是重试运行取当前会话模式，不取该轮 `modeSnapshot`，需一并处理。
- 直接教学仍可用图、plan 和提问组件，但减少提问。

## 遗留风险

学生可能过度使用按钮，少了思考。一期不限次数，T6 观察后再定是否加提示。
