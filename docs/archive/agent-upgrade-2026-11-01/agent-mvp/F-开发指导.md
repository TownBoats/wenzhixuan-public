# 阶段 F · 开发指导（取消、重试与验收）

> 本文件是 `F-取消重试与验收.md` 的**简版操作手册**：只回答「先做什么、怎么检查」。
> 设计与理由不在这里重复——那是阶段文件的职责；验收清单以 `docs/AGENT_MVP_PLAN.md` 第 6 节为准。
> 本文件不含阶段文件中没有的新设计；发现缺口按规则 §1「文档维护规则」处理。

## 1. 目标

补齐「出错时会发生什么」，并把前面五个阶段的结论落到可检查的证据上。四条判据（来自阶段文件 §1 / §5）：

1. **取消**能停住：主副两个请求都中止，已收到的内容保留，且**不显示为错误**。
2. **重试**只作用于最后一轮：换新 `runId`，不产生重复工具卡、重复工具消息、旧流污染。
3. **错误可读**：端点不支持工具 / 副模型失败 / 保存失败 / 超时 / 取消，各有明确落点；错误里不出现密钥。
4. **验收成表**：总纲第 6 节清单逐项有结果（含端点、模型、日期），并据此决定 18 日投递版本。

## 3. 分步操作

### F1 · 取消（补证据为主，代码可能不用改）

**做法要点**
- 页面入口已存在，不要新造第二个取消按钮。
- 要补的三件证据：① 副模型请求确实被中止（请求计数或运行层日志，**不接受「代码里传了 signal」这种声明**）；② 取消后 `turn.error` 为空、页面不显示错误块；③ 取消后立刻能再次发送。
- 取消与超时必须区分：超时是 `failed`（可重试、有提示），取消是 `cancelled`（不算错误）。

**你检查**
- 点取消后界面 1 秒内不再增长；网络面板里主请求显示 aborted。
- 该轮落盘状态是 `cancelled`，没有 `error` 文案。
- 取消期间若有迟到事件（可模拟），状态不变。

**命令**：`node --test "src/utils/__tests__/*.test.js"`（C3 已有迟到/取消用例）+ 浏览器实测。

### F2 · 重试最后一轮（唯一要新写界面的一步）

**做法要点**
- 在页面加一个「重试」入口，只在 `session.canRetryLastTurn` 为真时出现（失败 / 取消 / 中断的最后一轮）。
- 点击调 `session.retryLastTurn()`；**保留原内容**直到新内容到达，界面显示「重新生成中…」（新增翻译键）。
- 不新增命令、不改 hook：`retryLastTurn` 已存在且已验收（C-1 结论 3）。

**你检查**
- 重试后协议消息里 `ask_question` 只出现一次；工具卡不重复。
- 连续点重试只产生一次运行（第二次是空操作）。
- 重试过程中点取消，状态回到可输入。
- 重试不会把旧轮的正文拼到新正文后面（`runId` 不同 → 另起片段）。

**命令**：E4 的签名用例（确认重试后签名变化）+ 真实端点实测。

### F3 · 错误映射

**做法要点**：把 `turn.error` 按阶段文件 §4 的表格分类，页面显示可读文案：

| 情况 | 界面 |
| --- | --- |
| 端点不支持工具调用 | 「当前模型不支持工具调用」+ 端点与模型名 + 已降级说明 |
| 副模型失败 | 问题卡仍在，显示「候选答案生成失败，可以直接输入回答」（D8 已实现「可以点击回答」+ 浮层，保留） |
| 保存失败 | 「对话未能保存到本地」+ 可执行动作（E3/E5 已实现，不要重做） |
| 超时 | 「请求超时」，**无自动重试提示** |
| 取消 | 不显示为错误 |

- 错误里可以出现端点与模型名（不是密钥）；**不允许**出现 `apiKey`、请求头、用户配置。

**你检查**：五种情况各触发一次并截图/摘录文案；文案里 grep 不到 `apiKey`；没有任何「静默退回旧路径」的行为。

**命令**：`npx eslint` 改动文件 + 浏览器实测（失败链路可用假端点或错误模型名触发）。

### F4 · 逐项验收

**做法要点**
- 打开 `docs/AGENT_MVP_PLAN.md` 第 6 节清单，逐条执行并记录：端点、模型、日期、结果、未通过项的现象。
- 统一用「闭包」这一主题走正常链路与失败链路（与 A2/B7/D8 对齐，便于定位差异）。
- **补旧路径 6 项走查表**（HANDOFF 第 5 节首条至今未填）：一轮多题、作答后自动续轮、重试最后一条等，必须在 `agent_runtime` 关闭下逐项确认。
- 产出：验收表 + `决策记录.md` 的 F 阶段条目 + **决策 1（投递版本）与决策 2（开关去留）的结论**。
- 复核主包体积（2,895.51 kB，相对 A2 基线 +163 kB），在决策记录里说明是否可接受。

**你检查**
- 清单每一项都有独立证据，不接受「整体跑了一遍，都正常」。
- 未通过项写清现象与原因；简历表述只写已通过的能力。

**命令**：全部基线命令 + `npx vite build` 的产物大小。

## 4. 通过标准

1. 取消、重试、错误映射各有现场证据（含副模型中止的计数、重试后 `ask_question` 只出现一次）。
2. 总纲第 6 节清单逐项有结果，含端点、模型、日期。
3. `node --test "src/utils/__tests__/*.test.js"` 全绿且条数只增不减（≥98）；agent 45/45；`session-loop.mjs` 17/17。
4. `npx eslint .` 回到 18 problems（15/3）或更少；`npx vite build` 通过。
5. 旧路径（`agent_runtime` 关闭）行为不变，6 项走查表填完。
6. `决策记录.md` 有 F 阶段条目，18 日投递版本与开关去留有明确结论。

## 5. 本阶段不要做

- 不做「任意轮重试 / 从中间重来」；不做自动重试（重试策略留给上层，`maxRetries: 0` 不变）。
- 不删旧路径（清理排在投递之后，`决策记录.md` 决策 2 明确）。
- 不改协议字段、不改 `src/pages/ChatPage/`、`src/lib/AgentModel.js`、`src/hooks/useStreaming.js`、`src/utils/StreamingParser.js`。
- 不升级依赖、不引入状态库、不为了「看起来更好」改 UI 视觉。
- 不把「跨刷新的外部服务恰好执行一次」当成能力声明（阶段文件 §7 已排除）。
