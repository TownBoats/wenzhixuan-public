# 阶段 A 开发指导：基线与端点验证

> 详细理由、决策点和监督方法见 `A-基线与端点验证.md`；本文件是可直接照做的简版。

**目标**：动手写代码前，先确认两件事：依赖版本和锁文件一致；你的模型端点真的支持工具调用。这个阶段不写产品代码，预计 1.5 小时。

## 开工前准备（约 5 分钟）

1. 准备一个主模型端点：base URL、模型名、密钥。最好再准备一个带"思考模式"的模型。
2. 在终端里设置环境变量。密钥不要贴进对话：
   ```bash
   export PROBE_BASE_URL=...
   export PROBE_API_KEY=...
   export PROBE_MODEL=...
   ```

## 四步走

### 第 1 步：对齐依赖（A1）

```bash
pnpm install --frozen-lockfile
node -p "require('ai/package.json').version"              # 应为 6.0.177
node -p "require('@ai-sdk/openai/package.json').version"  # 应为 3.0.63
node -p "require('zod/package.json').version"             # 应为 4.4.3
git status                                                 # package.json 和锁文件不应有改动
```

**你检查**：三个包的版本号与锁文件一致。如果版本对不上，先停下来，不要继续。

### 第 2 步：存档基线（A2）

```bash
npx vite build
npx eslint .
```

把错误数量记下来，目前已知是 15 个错误、3 个警告。然后打开浏览器，把旧版走一遍：发送消息 → 等它提问 → 选一个档位作答 → 自己输入作答 → 切换历史会话 → 重试。每一项记"正常"或"异常"，并写下看到的现象。

**这一步的意义**：你现在看到的行为，就是之后验收新版本时的对照标准。

### 第 3 步：端点探针（A3）

这一步交给 AI 写脚本，可以直接复制下面的提示词：

```
我在做问知轩 Agent 改造的阶段 A · 任务 A3。
请先阅读 docs/agent-mvp/HANDOFF.md、README.md、01-核心协议.md 和 A-基线与端点验证.md。

只新建 scripts/probe-tools.mjs，不改其他文件，不装新依赖。
配置从环境变量 PROBE_BASE_URL / PROBE_API_KEY / PROBE_MODEL 读取。
跑文档里的 5 个用例，每个用例打印"通过 / 失败 / 不支持"和原始输出（密钥打码），
并打印 response.messages 的结构和总步数。

动手前先复述你的理解和不确定的地方，等我确认后再写。
```

然后运行 `node scripts/probe-tools.mjs`。

**你检查**：

| 用例 | 看什么 |
| --- | --- |
| ① 工具参数 | 打印出的工具名和参数是一个对象，而不是正文里的一段 JSON 文本 |
| ② 第二步生成 | 步数为 2，第二步有新文本 ← **最关键** |
| ③ 思考模型 + 工具 | 第二步没有报 400 |
| ④ 开闸标记 | `response.messages` 里是否出现零宽空格（这一项是确认问题存在，不算失败） |
| ⑤ `parallelToolCalls` | 请求被接受了，还是被拒绝了 |

**追问 AI**："你怎么确认第二步真的发生了？把步数贴给我。"

### 第 4 步：记录结论（A4）

让 AI 按模板把结果追加到 `决策记录.md` 的 A 阶段（依赖版本、端点和模型、5 个用例的结论、基线数据），并更新 `HANDOFF.md`。

## 通过标准

- ✅ 用例 ① 和 ② 都通过：进入 B 阶段。
- ❌ 用例 ② 失败：先换端点或换模型，再测一次（对应 A 文件里的决策 2），不要开始写 UI。
- ⚠️ 只有用例 ③ 失败：可以继续，但要在决策记录里写明，B 阶段先用非思考模型开发。

## 本阶段不要做

- 不升级依赖，也不修 lint 里已有的错误。
- 不改 `src/` 下的任何文件。
- 不接受只用 mock 得出的"验证通过"。
