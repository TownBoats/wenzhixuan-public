# 阶段 D 开发指导：页面接入、模式与设置迁移

> 详细理由、决策点与监督办法见 `D-页面与模式.md`；数据结构与协议以 `01-核心协议.md` 为唯一事实源。本文件是可直接照做的简版操作步骤。

**目标**：让已经成立的协议与状态机在真实界面上可见、可操作——浏览器里走通「输入 → 工具卡 → 问题与候选答案 → 作答/跳过 → 反馈」，并用显式模式取代「靠比对提示词猜模式」。

预计 2.5 小时。本阶段允许改：`src/pages/AgentChatPage/`（新增）、`src/components/{MessageContent,ToolCallCard}/`（新增）、`src/App.jsx`（仅加开关）、`src/utils/promptMigration.js`（新增）、`src/locales/{zh,en}/translation.json`（只加键）、`src/utils/__tests__/`。**不改**旧路径四件套（`ChatPage` / `AgentModel` / `useStreaming` / `StreamingParser`）、不改 `src/agent/**`、不改依赖。

### 2. 带着 C 阶段的三条结论开工（`决策记录.md` C-3，不得推翻）

1. **页面只发命令、不写状态**：`useChatSession` 返回 20 个键（11 只读 + 9 命令），没有 setter、没有 `dispatch`。页面不得新增可写状态来表达「是否在运行 / 有哪些待答问题」，一律用 `isRunning` / `pendingQuestions`。
2. **渲染数据的唯一来源是 `renderedTurns`**（`projectTurns` 的投影：`blocks` 有序、`questions` 按调用顺序、`toolCards` 带四态）。不要直接读 `turn.parts` 自己拼。
3. **答案由 `submitAnswer` / `skipQuestion` 提交**，两者内部完成「写答案 → 全部结束后开下一轮」。页面**不要**自己拼答案文本、不要自己触发下一轮。

## 分步操作

### 第 1 步：D1 · `App.jsx` 运行时开关

**做法要点**

- 读 `localStorage.agent_runtime`，为真渲染新页面，否则渲染现有 `ChatPage`；开发期**默认关**。
- 只加开关与引用，不重构 `App.jsx` 其它部分。

**你检查**

| 看什么 | 期望 |
| --- | --- |
| 默认值 | 键不存在时走旧路径 |
| 回退成本 | 把键删掉即回到旧路径，不需要改代码 |
| 旧路径 | 开关关闭时 6 项行为与 A2 走查一致 |

**命令**

```bash
npx eslint src/App.jsx
npx vite build
```

### 第 2 步：D2 · 模式控件 —— ✂️ 已裁剪

不做。依据 `决策记录.md` **B-1**（取消用户可见的模式切换）。代码层的兜底模式仍然存在（`normal` 不注册工具），但界面不暴露。本步只需在交付说明里写一行「按 B-1 裁剪，未改动」。

### 第 3 步：D3 · `MessageContent` 与 `ToolCallCard`

**做法要点**

- `MessageContent` 按 `renderedTurns[].blocks` 顺序渲染文本 / 推理 / 工具；**不要**把工具卡统一挪到末尾。
- reasoning 渲染要节流：真实端点一轮可产生数百条 `reasoning-delta`（B7 实测 354 条），每条都会经 reducer 触发投影，渲染层用 `requestAnimationFrame` 合帧或等效手段，不得每条 delta 做一次整消息重渲染。
- `ToolCallCard` 覆盖四态：准备问题中 / 生成候选答案中 / 完成 / 候选答案不可用；三态用文字 + 图形区分，不只靠颜色；展开可键盘操作。
- reasoning 只显示接口真实返回的内容（`blocks` 里 `type:'reasoning'`），不生成任何「模拟思考」。

**你检查**

| 看什么 | 期望 |
| --- | --- |
| 顺序 | 同一条消息里「文本 → 工具 → 文本」的先后与实际发生一致 |
| 卡片数 | 同一 `toolCallId` 只有一张卡（不变量 5） |
| 四态 | 四种状态的文案都能在界面上找到，不靠颜色区分 |
| 错误可见 | 失败 / 降级原因在展开区能看到，不吞掉 |

**命令**

```bash
npx eslint src/components/MessageContent src/components/ToolCallCard
npx vite build
```

### 第 4 步：D4 · 本轮问题卡组

**做法要点**

- 复用现有 `QuestionCard` / `AnswerCard`，传入 `turn.questions`（按模型调用顺序），**卡片数＝问题数**。注意：这两个组件吃的是旧数据结构（`ContentParser` 结果、旧问题状态机），实际是「复用样式与交互、重写接线」——开工先核对 props 差异，必要时在新页面侧做一层薄适配，不为接线去改旧组件的行为。
- 三条路径都走命令：选项作答 → `submitAnswer({ questionId, answer, selectedLevel })`；自定义输入 → `submitAnswer({ questionId, answer })`；跳过 → `skipQuestion({ questionId })`。
- 候选答案按 `options.length` 渲染，**不得硬编码 5 行**；缺档时只显示实际存在的档位。`optionsStatus: 'unavailable'` 时显示可读提示并允许手动作答。

**你检查**

| 看什么 | 期望 |
| --- | --- |
| 三条路径 | 都能让本轮完成并进入下一轮 |
| 计数 | 卡片数与问题数一致，无重复卡 |
| 档位 | 3 档时只显示 3 行，不留空行 |
| 双击 | 连点两次只产生一次运行（依赖 reducer，不要靠 `disabled`） |

**命令**

```bash
npx eslint src/pages/AgentChatPage
npx vite build
```

### 第 5 步：D5 · 配置门槛

**做法要点**

- 苏格拉底模式**只校验主模型**；缺副模型时给可读提示（指向设置）并允许手动作答，**不切换模式**。
- 端点不支持工具时**不自动降级**（`决策记录.md` D-2：会话层只暴露错误文本，没有可靠检测信号）：如实显示具体原因（含端点与模型名），并建议用户手动切换常规模式。

**你检查**

| 看什么 | 期望 |
| --- | --- |
| 只配主模型 | 能进入苏格拉底模式，问题卡可手动作答 |
| 缺副模型 | 提示指向设置，不阻断、不切模式 |
| 端点不支持工具 | 显示具体原因（含端点与模型名）+ 建议切换常规模式 |

**命令**

```bash
npx eslint <改动文件>
```

### 第 6 步：D6 · 提示词迁移判定

**做法要点**

- 判定规则（`D-页面与模式.md` 2.2）：存储值与「中英任一份当前内置提示词的原文」**完全相等** → 视为未自定义、忽略；否则视为已自定义、**不拼接**，在设置页显示提示。
- 旧协议的 `〖response〗/〖question〗` 标签规则不得进入系统提示。
- 设置面板同步落地 `决策记录.md` D-1：主模型面板移除模式下拉与 `TEST_MODE` 预设，副模型面板保留。`AgentConfigPanel` 被旧路径共用且不在四件套保护名单里——开工前先选定「按 `agent_runtime` 区分两种面板形态」还是「接受旧路径设置面板一并变化」，选定后写进交付说明。

**你检查**

| 看什么 | 期望 |
| --- | --- |
| 内置值 | 中英文两版、以及语言切换写回的缓存值都判为「未自定义」 |
| 改过一个词 | 判为「已自定义」，且提示只出现一次、可关闭 |
| 系统提示 | 只由模式决定（`buildSystemPrompt`），用户提示词没有入口 |

**命令**

```bash

npx eslint <改动文件>
```

## 通过标准

- 正常链路与失败链路都有记录（截图或逐步文字），D8 用同一主题。
- `agent_runtime` 关时旧路径 6 项行为与 A2 一致；`git status` 显示旧路径四件套未被改写。
- 同一 `toolCallId` 只有一张卡；卡片数＝问题数；候选答案按 `options.length` 渲染。
- 页面拿不到任何状态 setter；不新增可写布尔量表示运行状态。
- `npx eslint .` 不超过 15 错误 / 3 警告；`vite build` 通过。
- 协议不变量 1–8 逐条自检有结论（尤其 2：界面与协议消息都无 U+200B；3：reasoning 不进上下文）。

## 本阶段不要做

- 不改旧路径四件套、不改 `src/agent/**`、不改 `useChatSession` / `conversationState` 的对外行为。
- 不做会话状态层的重写（C 阶段已验收）；不在页面里拼答案文本或触发下一轮。
- 不接历史存储（E 阶段）、不做取消/重试的界面入口（F 阶段）。
- 不引入状态库、不做 TypeScript 迁移、不改依赖、不做全站 UI 重设计。
