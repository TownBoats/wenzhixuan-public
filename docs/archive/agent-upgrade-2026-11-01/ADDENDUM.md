### ARCHIVE-2 资料纳入版本控制并同步主分支

日期：2026-11-01

问题：用户要求提交并推送当前开发进度，再同步到 main。原 `.gitignore` 整体排除 `docs/`、`.agent`、`.codebuddy`，按原状提交只会带上根 `AGENTS.md` 与 README，Harness、业务知识和历史归档不会进入远端。

选项：① 只提交已跟踪源码与根入口，资料继续留在本地；② 整体强制加入忽略目录（含本机团队状态）；③ 跟踪 `docs/` 与两个短规则入口，继续忽略 `.codebuddy/teams` 等本机状态。

结论：③。`.gitignore` 改为仅忽略本机工具状态并放行规则目录；提交前扫描暂存内容，未发现真实密钥，仅历史文档中存在假 key 与掩码示例。阶段提交包含 77 个文件（+13,434/−733），dev 推送后以 `--ff-only` 同步 main。

原因：Harness、现行知识与短交接是后续开发的入口，只留本地会让远端代码与文档脱节；整体强加会带入本机会话与团队数据，也会把不必要内容永久写入历史。

放弃：① 无法让远端接手者读到方法和现行知识；② 违背选择性跟踪与敏感资料复核原则。

验证：提交与推送成功，`git ls-remote --heads origin main dev` 显示两条引用指向同一提交；具体哈希见 Git 日志。归档 30 项 SHA-256 校验通过，活动文档本地链接检查通过。本轮未运行产品测试、ESLint 全量或构建。

遗留：自动验证仍需在依赖可用后重跑；`.codebuddy/teams` 等本机状态不入库；后续资料修改若需忽略，应按路径逐项配置，不恢复整目录忽略。
