## 历史解释与勘误

原文保留，以下说明防止将旧叙述误当现状：

1. HANDOFF 同时含“G 待验收”和“G 已验收”的旧快照；最终用户表态为 2026-11-01 G-2「我人工验收了」、G-1「ok，验收完毕」。A–G 阶段已关闭；当前 HEAD 自动复验不足另记，不能由人工验收推出自动通过。
2. 架构图标注 2026-10-16 目标设计；后续实际新增三工具、参数流式事件和结构化候选答案。现行事实见 [业务知识](../../knowledge/agent-upgrade.md)。
3. B-10 中副模型经 `modelAdapter` / 标签解析的方案后来已被代码替代。当前使用非流式 `generateText` + 强制 `submit_options`；细节见现行知识与提交记录。
4. `MarkdownRenderer` 并非只有死代码引用；新路径经 `AnswerCard` 使用。`SettingsPanel` 目录有被新配置面板使用的共享组件，不能整目录删除。
5. “旧路径一行没改”不准确：升级 diff 中 `ChatPage.jsx` 增加 1 行，若干共享组件也有改动。“旧路径总体保留、没有删除文件”是准确口径。
6. `+13,210 / -75` 表示两提交端点 diff 中新增/删除的物理行，净增为 `13,135`；不表示累计敲击量。新增行包含测试、文案、脚本、指令和配置，不能据其占比声称“重写了 57% 的业务代码”。
7. `node --test` 的 `118 tests / 110 pass / 8 fail` 中，8 项是测试文件因缺依赖加载失败，不能把 118 记为完整用例总数，也不能说代码已全部验证正常。
8. junction 排障出现过把会话侧限制推广为机器级故障、把锁文件健康与代码正确说成定论的叙述。现有证据不足以证明这些结论；应保留报错及环境边界，不据此改包布局或迁移仓库。
9. 归档中的 `react-markdown@10` 叙述与当前依赖不符：本轮读取 `package.json` 为 `^9.0.3`，用户重装输出为 `9.1.0`。实际解析以锁文件为准。
10. 静态 `dist` 走查未关联可核验的当前源码构建基准，不作为当前 HEAD 新构建成功的证据。
